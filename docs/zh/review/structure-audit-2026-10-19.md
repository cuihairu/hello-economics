## 问题清单与严重度

1. **中：课程编号仅存在于侧栏数据，文件名与正文标题采用另一套呈现。** 例如目录数据编号从 `courses.ts:69-81` 起，文件 `docs/math/集合与逻辑.md` 本身无数字前缀；其他课程同理。影响：离线浏览、文件列表排序和侧栏编号之间不能直观看出映射；但当前侧栏链接正常且编号序列连续。建议统一评估是否要把编号变成稳定元数据，不建议贸然重命名 URL。
2. **中：辅助专题与主课程内容共处同一平面目录。** `docs/western/` 同时放主章节、`History.md`、`西方经济学公式总览.md`、`宏观经济模型演进.md`（见 `courses.ts:94-97`）；`docs/socialist/` 也将主章与会议专题并列（`courses.ts:230-232`）。读者理解成本来自角色混放，不是入口缺失；脚本验证无孤立页。
3. **低：大小写与命名样式混用。** 六个课程中的 `Readme.md`、`History.md` 使用英文首字母大写（例如 `docs/finance/Readme.md`、`docs/international/History.md`），同时正文使用中文文件名，根目录还采用小写英文入口名及中文 `审计-文档一致性.md`；参考资料中 `docs/reference/notes/金融学-笔记.md` 使用 ASCII 连字符。大小写敏感的部署环境可能增加手工维护失误，但现有链接检查未发现错误。
4. **低：根级入口风格混杂但职责可辨。** 根目录七个英文 slug 入口与一篇中文审计页并列（`docs/index.md`、`docs/审计-文档一致性.md` 等）；属于用户导航页和内部治理文档相邻，可能让贡献者误把审计页当读者入口。侧栏脚本仍将全部页面覆盖。
5. **低（已排除重大问题）：未发现编号断档、跳号或重复。** 文件名数字前缀抽取为 0 项；按真实侧栏章节数据核对，六条主序列均连续且无重复（`courses.ts:69-252`）。因此不存在可列出的“问题编号”。
6. **低（已核实无问题）：侧栏覆盖与 Markdown 内链。** `npm run check:sidebar` 与 `npm run check:links` 的运行结果如上；死链数量为 0。

## 判断与推荐

当前实际是 **5 套轴**。建议保留为 **3 套概念组织**：①课程章节（六门课程与其编号主序列）；②跨课程主题入口（知识点、时间线、人物、书籍、术语）；③参考资料/治理文档（reference 与审计类文档）。History、公式总览、导论等作为课程轴中的明确子类/元数据，不另立一套导航体系；文件系统可以继续按课程目录存放。理由：当前每页均有入口、章节序列完整、内链无死链，主要问题是辅助页与主章的角色标识和命名约定，不是目录树本身失效。不要为了凑成一致而把主题页强制塞入章节编号。

### 其实不乱、不用动的部分

- 六个课程 slug 清楚且稳定；课程正文按课程归档的一级目录方式合理。
- 主章节侧栏编号连续，西方经济学按微观/宏观分组，目录符合阅读路径（`courses.ts:101-126`）。
- 课程目录是单一数据源，侧栏、课程切换条与首页共用（`courses.ts:1-5`），避免多份手工目录漂移。
- 全部 94 篇页面有导航或文内入口；740 条 Markdown 链接无死链（脚本结果）。
- `reference/notes/` 作为旧笔记归档有明确用途；图片与 public 静态资源目录也不属于文档结构乱象。
- `README.md` 与 `README.zh.md` 是有意区分的双语仓库说明，不是重复 README；根目录 `PRODUCT.md`、`STYLE.md` 是项目说明材料，`todo.md` 是工作记录。`.tmp-covers/` 名称像临时目录但用途/是否仍需保留未核实；根目录 XMind 文件是源材料，不应仅凭扩展名判为杂物。
